# todo.md — План разработки

## Этап 0 — Подготовка и настройка окружения ✅

- Создать директорию проекта: `woo-seo-hilt/`
- Инициализировать Node.js проект:
    - `npm init -y`
- Установить зависимости:
    - `fetch` — запросы к WooCommerce API
    - `dotenv` — переменные окружения
    - `zod` — валидация схем
    - `chalk` / `cli-table3` — вывод в CLI
    - `fs-extra` — работа с файлами
    - `diff` — генерация diff
    - `jsdom` или `html-validator` — проверка HTML
- Создать файл `.env` с переменными:
```env
WC_URL=https://your-site.com
WC_CONSUMER_KEY=xxx
WC_CONSUMER_SECRET=xxx
```
- Базовая структура папок:
```
data/
    cache/
    backups/
src/
    commands/
    services/
    lib/
    schemas/
```

## Этап 1 — MVP: базовый экспорт/импорт + валидация 🚀

### 1.1 Клиент WooCommerce
- Файл: `src/lib/woocommerce.js`
- Реализовать:
    - `getProducts(ids?: number[])` — загрузка товаров, фильтрация по ID (поддержка до 50)
    - `updateProduct(id, data)` — частичное обновление через API

### 1.2 Экспорт в JSON
- Файл: `src/commands/export.js`
- Опции: `--ids` (список через запятую), `--category` (опционально)
- Логика:
    - Загрузить товары через `getProducts`
    - Привести к схеме экспорта (разрешённые поля, разворачивать изображения: `src`, `alt`, `title`)
    - Сохранить: `data/cache/export_<timestamp>.json`
    - Вывести путь к файлу

### 1.3 Схема валидации для импорта
- Файл: `src/schemas/import.schema.js` (Zod)
- Разрешённые корневые поля: `id`, `title`, `meta_title`, `meta_description`, `description`, `short_description`, `images`
- `images` — массив объектов с полями `alt?`, `title?` (запретить `src`)
- Типы: строки, числа, булевы
- Функция `validateImportData(data)` → ошибка или очищенные данные

### 1.4 Импорт с валидацией
- Файл: `src/commands/import.js`
- Опция: `--file` (путь к JSON)
- Логика:
    - Прочитать JSON и прогнать через `validateImportData`
    - Проверить, что все `id` существуют в кэше (загрузить актуальные данные)
    - При ошибках — вывести и остановиться
    - Создать бекап текущих затронутых товаров: `data/backups/backup_<timestamp>.json`
    - Выполнить `updateProduct` для каждого изменённого товара (только изменённые поля)
    - Вывести отчёт: сколько обновлено, сколько пропущено

### 1.5 Preview изменений (diff)
- Файл: `src/services/diff.js`
- Функция: `generateDiff(oldProduct, newProduct)` — список изменений
- В `import.js` перед импортом:
    - Загрузить текущие товары по списку `id`
    - Для каждого товара сгенерировать diff и вывести (таблица: ID, поле, старое → новое, обрезать длинные строки)
    - Запросить подтверждение (Y/n) перед записью

## Этап 2 — Улучшения безопасности и удобства 🧪

### 2.1 Работа с изображениями
- При экспорте включать: `id`, `src`, `alt`, `title`
- В схеме импорта разрешить изменение `images[].alt` и `images[].title`
- В `src/lib/woocommerce.js` добавить `updateProductImages(productId, images)` (PUT `/products/<id>`)
- При импорте обновлять только `alt`/`title`, не менять `src`

### 2.2 Валидация HTML перед импортом
- Установить `html-validator` или использовать `jsdom`
- Файл: `src/lib/html-validator.js`
    - Проверять закрытие тегов
    - Находить незакрытые/лишние теги
    - Проверять наличие `alt` в `img` (предупреждение, не блокировка)
- В `import.js` после diff запускать проверку HTML для `description`, `short_description`
    - При критических ошибках — предложить прервать или продолжить с предупреждением

### 2.3 Откат последнего импорта
- Команда: `src/commands/rollback.js`
- Поиск последнего бекапа в `data/backups/`
- Восстановление товаров через `updateProduct`
- Запрос подтверждения перед откатом
- После отката создавать новый бекап

## Этап 3 — CLI и вспомогательные утилиты 🖥️

### 3.1 Главный CLI
- Файл: `src/cli.js` (указать `"bin": "./src/cli.js"` в package.json)
- Команды:
    - `export`
    - `import`
    - `preview` — показать diff без записи
    - `rollback`
    - `analyze` — запустить SEO-анализатор на кэшированных товарах

### 3.2 SEO-анализатор
- Файл: `src/services/analyzer.js`
- Функции:
    - `checkTitleLength(title)` → `good|warning|error`
    - `checkMetaDescription(desc)`
    - `checkHtmlStructure(html)` — H1, таблицы, списки, alt
    - `calculateSeoScore(product)` → 0–100
- Команда `analyze` выводит таблицу товаров с Score и подсвечивает проблемы

### 3.3 Кэширование товаров
- Файл: `src/services/cache.js`
- Хранить `data/cache/products.json` — обновлять раз в час или по запросу
- При импорте/экспорте использовать кэш, обновлять при необходимости
- Команда: `cache:refresh` для ручного обновления
